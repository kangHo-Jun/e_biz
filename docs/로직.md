# 품목명 & 코드 생성 로직
**door_v4.gs | 최종: 2026-07-15**

---

## 0. 출력 열 구조

| 열 | 컬럼 번호 | 내용 |
|----|---------|------|
| BA | 53 | 품목명 (`생성_품목명`) |
| BB | 54 | 코드 (`생성_품목코드_NEW`) |
| BC | 55 | (빈칸) |
| BD | 56 | 단위 (틀 / 짝) |
| BG | 59 | 추가 품목명 (`프레임몰딩` 조건부) |
| BH | 60 | 추가 코드 (`PM`/`PP` 조건부) |
| BJ | 62 | 단위 (`EA`, 조건부) |
| BK | 63 | 구분 (`주문재`, 조건부) |

- 행 범위: 12~42 (`CONFIG.START_ROW` ~ `CONFIG.END_ROW`)
- 문틀 행: 12~26 (`FRAME_END`)
- 문짝 행: 30~42 (`DOOR_START` ~ `DOOR_END`)
- BA/BB는 동일 원본 입력(AP/AW/AX/AS/AT/AV/AQ열)에서 각각 별도 함수로 생성

## 1. 품목 타입 판별 (`구분_품목타입`)

```
row >= DOOR_START(30) → DOOR (행 번호 우선)
AP에 ['문틀','발포','분리형','스토퍼','슬림형','와이드형'] 포함 → FRAME
그 외 → DOOR
```

> ⚠️ 행 번호가 최우선이므로, 30행 이상은 AP값과 무관하게 DOOR로 처리된다.

## 2. 품목명 생성 (`생성_품목명`)

### 2-1. 공통 구조

```
[색상] + [품명] + [규격]
```

### 2-2. 타입별 분기

**FRAME (문틀 계열)**
```
출력: [색상_전처리(AW,AX)] + [품명_전처리(AP)] + [AS숫자*AT*AV + 식기표시]
예: 영림PS010 발포 와이드 130*1132*2123식기무
```

**DOOR (문짝 계열)**
```
출력: [색상_전처리(AW,AX)] + [품명_전처리_문짝(AP)] + [AT*AV + 식기표시]
```

### 2-3. 색상 전처리 (`색상_전처리`)

AW(색상명) + AX(색상코드) 조합 후 아래 순서로 처리:

| 입력 패턴 | 출력 |
|---------|------|
| 영림{숫자} + 영문+숫자 | 공백 제거 전부 출력 (예: 영림116PS010) |
| 영림{숫자} + 한글 | 한글 제거 (예: 영림116) |
| 영림{숫자}(코드) | 괄호 제거 내용 유지 (예: 영림116PS010) |
| 순한글 | 공백 제거 (예: 시나몬월넛) |
| 그 외 | 영림/우딘/예림 제거 후 나머지 반환 |

### 2-4. 품명 전처리 (FRAME) (`품명_전처리`)

```
1. 영림ㅣ 제거
2. ㅣ를 공백으로 변환
3. '문틀', '형' 제거
4. \d+바 제거
5. (식기X/O) 제거
```

**고정 매핑 (특수 AP값):**

아래 AP값은 일반 전처리 대신 고정 품명으로 출력된다.

| AP값 키워드 | 출력 품명 |
|-----------|---------|
| 히든ㅣ목문틀 | 히든도어 전용문틀 |
| 히든ㅣ알루미늄 문틀 | 히든 알루미늄 문틀 |
| 스텝도어ㅣ전용문틀 | 스텝도어 전용문틀 |

### 2-5. 품명 전처리 (DOOR) (`품명_전처리_문짝`)

```
'문틀', '(식기X/O)' 제거 → AS의 첫 숫자+한글 패턴 제거
```

## 3. 코드 생성 (`생성_품목코드_NEW`)

### 3-1. 코드 구조

```
[브랜드/색상코드] + [플래그코드(FRAME) 또는 모델코드(DOOR)] + [규격코드(FRAME만)]
```

### 3-2. 브랜드/색상코드 (`브랜드색상코드_생성`)

| 순위 | 패턴 | 출력 예 |
|-----|-----|--------|
| 1 | 영림{숫자}PS{숫자} | `Y116` |
| 2 | 영림{숫자} | `Y131` |
| 3 | P[A-Z]+숫자(-숫자)? | `YS140`, `YX4441`, `YSM140` |
| 4 | 순한글 | 앞 2글자 (예: Y시나) |
| 5 | 숫자 포함 fallback | 첫 숫자 |

### 3-3. 플래그코드 (FRAME) (`플래그코드_생성`)

AP를 `ㅣ`로 분리 후 `형` 제거한 토큰 배열로 처리한다.

**상위코드 (head) — 먼저 일치하는 것 1개만 적용:**

| 토큰 | 코드 | 비고 |
|-----|------|-----|
| 발포 | B | |
| 방염 | F | |
| 비방염 | N | |
| 알루미늄 | A | |
| 스텝도어 | T | |
| 무메 | M | |
| 목재 | W | |
| 프레임몰딩 | P | 예외 처리 (아래 참고) |

**하위코드 (tail) — 해당되는 것 모두 누적:**

| 토큰 | 코드 | 매칭 방식 |
|-----|------|---------|
| 슬림 | S | 부분 매칭 (indexOf) |
| 와이드 | W | 부분 매칭 |
| 분리 | D | 부분 매칭 |
| 히든 | H | 부분 매칭 |
| 미서기 | L | 부분 매칭 |

**케이스별 플래그코드 예시:**

| AP값 | 플래그코드 |
|-----|---------|
| 영림ㅣ발포ㅣ슬림형 | BS |
| 영림ㅣ발포ㅣ와이드형 | BW |
| 영림ㅣ발포ㅣ슬림 분리형 | BSD |
| 영림ㅣ목재ㅣ와이드형 | WW |
| 영림ㅣ목재ㅣ슬림형 | WS |
| 영림ㅣ목재ㅣ히든 | WH |
| 영림ㅣ히든ㅣ알루미늄 문틀 | AH |
| 영림ㅣ스텝도어ㅣ전용문틀 | T |
| 무메 30T | M |

**프레임몰딩 예외 처리:**

프레임몰딩은 상위코드 P이며, 하위코드는 PVC/MDF일 때만 조건부 적용된다.

```javascript
if(head === "P") {
  if(s.indexOf("PVC") !== -1) tail += "P";
  if(s.indexOf("MDF") !== -1) tail += "M";
}
```

| AP값 | 플래그코드 |
|-----|---------|
| 영림ㅣ프레임몰딩ㅣPVC | PP |
| 영림ㅣ프레임몰딩ㅣMDF | PM |

### 3-4. 모델코드 (DOOR) (`모델코드_생성`)

| 입력 패턴 | 출력 |
|--------|------|
| 영문-{코드} 형태 | 하이픈 제거 (예: YA-15 → YA15) |
| 탈공 포함 | `탈` |
| M/D + 민무늬 | `MD` |
| {문자}도어 | 앞 문자 반환 |

### 3-5. 규격코드 (FRAME) (`규격코드_생성`)

```
AS숫자 + AT + AV + 식기표시(AQ)
3방 → N / 4방 → Y
예: 130 + 1132 + 2123 + N → 13011322123N
```

### 3-6. BG/BH/BJ/BK 추가 출력

조건: AP가 아래 두 값 중 하나일 때만 출력

- `영림ㅣ발포ㅣ와이드ㅣ12T(MDF)`
- `영림ㅣ발포ㅣ와이드ㅣ9T(PVC)`

| 열 | 출력 내용 |
|----|---------|
| BG | `[색상] MDF 프레임몰딩 [AS값]바` / `[색상] PVC 프레임몰딩 [AS값]바` |
| BH | `[브랜드색상코드]PM[AS값]` / `[브랜드색상코드]PP[AS값]` |
| BJ | EA (고정) |
| BK | 주문재 (고정) |

그 외 모든 경우 BG/BH/BJ/BK는 빈값.

## 4. 문틀 치수 역계산 (`생성_문틀치수_히든`)

문짝 치수(AT31:AT49) 입력 시 대응 문틀 치수(AT12:AT30) 자동 계산.

**행 대응:** 문짝 31행 ↔ 문틀 12행, ..., 문짝 49행 ↔ 문틀 30행

**계산 공식:**

| AP값 | 폭 계산 | 높이 계산 |
|-----|--------|---------|
| 히든ㅣ알루미늄 문틀 | 문짝폭 - 104 | 문짝높이 - 48 - AZ(문짝행) |
| 히든ㅣ목문틀 | 문짝폭 - 88 | 문짝높이 - 40 - AZ(문짝행) |

**트리거:** AT31:AT49 편집 시 자동 실행 (onEdit)
